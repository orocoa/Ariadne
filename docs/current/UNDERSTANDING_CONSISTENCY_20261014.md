# 已保存更正的理解一致性修复

日期：2026-10-14。范围由用户锁定为理解一致性：专门 agent 实现、另一 agent 独立验收，保留来源、版本校验和人工保存，验收后仅本地提交。

## 问题与结果

修复前，Candidate 来源工作区和卡片对话没有完整接入已保存的个人更正；Job、个人理解和职位概况在预算选择中可能截短更正的必要关联依据。旧助手回复和旧用户引用也可能在补充撤回、替换或来源失效后重新进入模型上下文。独立基线在原 HEAD 上 14/21 通过，七个失败保留为修复依据。

现在六个对话入口共用当前有效的 `personal_context`：Candidate 整体/卡片、Job 整体/卡片、个人理解、职位概况。Candidate 精确匹配当前来源与 item 身份；跨材料的关联依据保持完整只读，编辑目标仍限于当前卡片。未关联的个人补充由模型判断相关性，不强套到某段经历。

- 已保存更正及其必要关联证据整条入模，再为其他材料分配剩余预算。整组放不下时返回 `PERSONAL_SAVED_CONTEXT_LIMIT`，不截断、不调用 Provider、不生成替代回复；其他无关材料仍适用已有有界检索。
- 当前有效的用户保存补充优先于旧材料与助手推断，但原始材料的冲突仍可解释；用户确认是自述确认，不等于外部事实核验。未保存提案不进入已保存上下文。
- Candidate 新回复保存本轮上下文 token；资料/补充变化后旧助手仍可见，但不再重新入模。替换、撤回或来源失效的保存原话及后续旧引用也被排除；本轮用户主动重新陈述仍保留为未确认自述。Personal 与 ResumeTask 复用同一历史失效边界。
- 四个后端 adapter 校验 bundle 的形状、指纹、关联与观察范围，并实际加入模型 payload。指纹用于完整性和绑定，不被宣称为事实真实性认证。
- 派发时捕获的来源与记忆 readset 在原领域成功写事务中再次核对。并发更新拒绝旧结果；本轮明确归档的新来源仅按精确 receipt 增补，不能刷新旧 readset 掩盖竞态。Job 不取得 Candidate 写权限。
- 前后端仍阻止模型宣称已自动保存/确认资料；修复了裸“已确认”造成的误报，允许“缺少已确认依据”与已有人工保存记录的正常说明。人工 Save 才追加确认版本，旧版本、原件与可见历史保持。
