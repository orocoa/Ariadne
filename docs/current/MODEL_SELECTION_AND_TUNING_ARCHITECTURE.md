# 统一模型选择与对话内调节架构

日期：2026-09-11。状态：**当前已验证模型的选择与参数链路已实现**。原架构约束保留，落地字段与验收范围见下方。

用户确认：首页简化模型名称，例如「GPT Sol」；对话框左下提供轻量切换入口，模型和推理强度在内部调整；后续其他模型复用同一架构。不自动更换当前模型，不因新增目录记录而授予执行资格。

## 2026-10-03 新 Codex 型号自动验证

本修订取代下文“新型号必须人工维护资格”的限制。内置 7 款历史资格保留；新增型号可通过 Skill 本机自动检查获得资格，无需编辑安装包内的型号清单。

- 模型菜单展示新型号与状态；首次点击「允许自动验证新型号」保存当前账号的持续授权，说明使用合成材料及 Codex 额度。此后打开菜单发现新型号时串行验证，菜单打开期间每 2 秒读取进度，关闭菜单停止轮询。关闭开关取消进行中的检查；失败、超时、上次中断均须显式重试，不循环消耗额度。
- 每次验证使用随机标记生成一张图片和两页 PDF，PDF 按实际生产路径完整转图。期望内容不进入提示或 schema；核对三张图片的顺序、精确内容、结构化输出、实际模型与 App Server 权限隔离。仅声明 text/image 且存在受支持强度的型号可以验证，优先使用 low，Ultra 不开放。一次基础兼容性通过不代表所有强度或真实职业任务质量均经过评测。
- 每 24 小时最多 3 次尝试，一次只运行一项；共享生产执行槽、180 秒模型等待上限与既有 PDF 预算。原子保存加文件锁负责跨线程/进程去重，过期执行标为中断，旧回执不能覆盖后续尝试。未通过的型号不能进入执行目录，不能绕过领域、版本或人工保存规则。
- 记录位于 Skill 数据目录的 `model-verification/state.json`，不写入安装包或职业资料库。只保存账号公开元数据的摘要、CLI 文件指纹、adapter/check 版本、模型、已测强度、材料 hash、结果与用量，不读取认证文件。账号更换需要重新授权；CLI 或检查代码更新后旧动态资格不再授予执行权，按新上下文重新验证。模型目录仍有最多 5 分钟缓存；动态型号的正式调用前强制重新发现，并在执行进程再次核对账号与 CLI 身份。
- 通过后刷新型号/强度目录，保留当前模型及未应用的选择；用户点击「应用」才更新本对话设置。原对话范围或设置修订变化会关闭陈旧菜单。损坏的验证记录不能授予资格，也不阻止既有内置型号显示。
- API 仅 Skill 开放 `/api/codex-verification`，接受带明确授权的开关或重试操作；不接受调用者提交的提示、图片、测试结果或资格状态。复用回环 Host/Origin 检查。Web 的 DeepSeek 更新机制保持独立。

## 1. 现状与目标

架构整理时本机 Codex 的 `gpt-5.6-sol` 身份固定在 [runtime_binding.py](../../src/runtime_binding.py)，调用参数固定为 `medium`，且忽略 Codex 用户配置，见 [codex_runtime.py](../../src/codex_runtime.py)。前端选择、能力门禁和配对回调也有同名特判。[RuntimeSnapshot](../../src/execution_contract.py) 与[浏览器快照](../../public/runtime-capabilities.js)尚未记录可调推理参数；[导入指纹](../../public/model-import-lifecycle-domain.js)同样未包含它们。只增加一个图标、改 CLI 参数或改模型字符串，都不能形成可靠的完整切换。

目标是**共用选择组件 + 共用选择解析 + 已验证模型目录 + 按 Provider/协议执行**，而不是给 Codex 单独做一套设置。复用当前 Runtime capability authority，不建立能绕过它的第二份“可执行模型列表”。

## 2. 用户看到的入口

| 位置 | 显示与职责 | 不承担的职责 |
| --- | --- | --- |
| 首页「运行方式」 | 简称，例如 `GPT Sol`；选择 Provider 与初始模型、连接服务、进入工作区；跨服务切换在此完成 | 不铺开推理强度、协议、完整 ID 和技术参数 |
| 对话输入框左下 | 附件 plus 旁的「图标 + Sol · 中 + 展开指示」，显示下一次发送的实际选择 | 不用难以辨认的纯图标，不混用附件按钮 |
| 向上弹出的选择菜单 | 列出首页当前 Provider 下所有已验证模型/强度组合，点选保存当前对话设置 | 不跨 Provider；不给不支持调节的模型伪造低/中/高控件；不展开连接或默认设置表单 |
| 本轮发送/附件确认 | 准确接收方、连接方式、完整模型 ID、实际参数及既有用途/额度提示 | 不用简称取代知情确认或执行身份 |
| 历史消息详情 | 当时真正使用的模型、参数与执行记录 | 不因当前选择变化而改写旧记录 |

沿用 Ariadne VI 图标、焦点和输入框组件：入口与 plus 同一底部操作区，发送按钮位于输入框内右下角。窄屏菜单限宽并可滚动；键盘可打开、选择、Escape 收起并返回焦点，屏幕阅读器名称包含当前模型与强度。布局遵循 [VI 系统](ARIADNE_VI_SYSTEM.md)，不生成新图标。

首页简称来自目录中的人工维护展示字段，不通过截断模型 ID 或关键词猜测。同一模型有多个连接时，可以先按型号分组，但必须让用户明确选定例如「本地 Codex」或「OpenAI API」，不得后台自动择路。简称相同的型号须加必要的版本/连接副标签以消除歧义。

## 3. 四层职责与数据

下表保留职责设计；实际字段以本页实施记录、参数目录与 execution_settings 校验为准。尚无独立多账号连接管理或任意模型接入 API。

| 层 | 关键数据/接口 | 唯一职责 |
| --- | --- | --- |
| Model Catalog（扩展现有 descriptor） | `model_key`、准确 `provider/model/protocol`、`short_label`、模型能力、各领域 operation 适配、`descriptor_revision`、`settings_schema`、经验证默认值 | 定义可用模型与其真实可调范围；展示元数据不赋予执行权限 |
| Connection（复用凭据/连接器） | `connection_id`、传输类型、连接/资格状态、受控 `credential_ref` | 区分模型与访问途径；凭据仍留在现有安全边界 |
| Selection（共用选择状态） | 默认偏好、对话覆盖、`selection_revision`；解析接口 `resolveSelection(scope, operation)` | 解析下一次请求选用哪一组合，不做模型调用，不改资料 |
| Execution（扩展现有 RuntimeSnapshot） | 实际组合、设置、版本、来源/上下文观察值、operation、consent、执行 ID | 提交时冻结、后端重验、调用唯一 adapter、核验实际回执 |

`model_key` 是目录的稳定控制标识，不是显示名；准确身份至少含 provider、model、protocol。`connection_id` 独立，不把登录账号、密钥或 token 编进可见 ID。后端根据允许的连接解析 credential_ref，不能让浏览器任意指定文件路径或凭据位置。

领域上下文与 Provider 传输继续分离：Candidate/Job/个人理解/职位概况负责各自 context、prompt、schema 与保存权限；Provider adapter 负责准确的模型、参数、材料编码及返回协议。同一型号只有完成某项 operation 的适配后，才能在该入口执行。

## 4. 默认值、当前对话与跨页规则

保留全局 **Local/Model 模式门禁**；新增分层的模型偏好，不把模式和模型参数混为一件事。

- 首页选中的模型保存为当前浏览器 origin 的应用默认值，不同步到其他浏览器或 Codex 开发任务。初次接入保持已验证默认强度；当前 Codex 是 medium。用户尚未决定全局改为 low，本次不改变默认。
- 未做覆盖的对话继承应用默认值，触发器显示实际生效组合。同 Provider 内的显式覆盖保留；首页切换 Provider 后，旧服务覆盖不再生效但不删除，各对话下一轮受新 Provider 约束，并刷新可见标签。
- 对话内切换模型或参数后，保存**完整的一组选项**作为当前对话覆盖，不把模型来自覆盖、强度来自后来改变的全局值混合。刷新后恢复该覆盖。
- 状态层保留显式设为默认与清除本对话覆盖的能力；简洁菜单不暴露这两项操作，点选只改变当前对话，首页继续负责应用默认。
- 当前对话按领域稳定身份定位：Candidate 工作区绑定其同源 conversation，Candidate/Job 独立详情绑定各自 conversation；个人理解与职位概况使用各自独立的稳定会话/范围键。没有既有 conversation_id 的入口应建立命名空间明确的 selection scope，不用跨领域共用的字面量代替身份。Working 版本不进入会话选择键，防止每次编辑丢失偏好。
- 同一个真实 conversation 在不同入口/标签页恢复同一选择；不同 conversation 不连带修改。存储使用与资料一致的 origin 隔离，内容仅为非敏感选择；覆盖写入需 revision 检查及跨标签通知。发生冲突时刷新选择并要求重新确认，不能静默覆盖。
- `resolveSelection(scope, operation)` 是唯一解析入口：Local 门禁优先；Model 下只解析首页 Provider 内的当前对话覆盖、兼容旧偏好或应用默认，再验证模型、连接、operation 和参数。无资格/不可用时明确阻止，不退回另一个模型或自动选择更强模型。
- 旧版 `ariadne-operation-runtimes-v1` 按 operation 分配的选择继续保留。同 Provider 差异如实显示，可通过菜单建立当前对话覆盖；跨 Provider 旧偏好不可覆盖首页，也不抹除其原始记录。

全局切换到 Local 后，所有 AI 发起入口继续受禁用/隐藏约束，对话覆盖原地保留但不能恢复 Model 执行。回到 Model 后重新验证原选择；不修改历史资料，也不自动换模型。

## 5. 参数能力驱动，不做通用假旋钮

`settings_schema` 按具体模型、operation、adapter 版本声明允许字段、类型、合法值、互斥约束、展示文案及经验证默认值。初期只开放**推理强度**；不顺带开放 temperature、输出预算、工具权限、服务等级或任意 CLI 参数。

- 以 `reasoning_effort` 表达确有这种能力的模型设置，但低/中/高是显示标签，adapter 必须映射到经验证的真实取值。不同 Provider 同名档位不承诺相同速度、质量或算力。
- 不支持或未验证的选项隐藏/不可执行；固定设置模型只显示单一名称选项。不得让用户选了 low 却仍执行 medium。
- 换模型时，使用该目标模型先前显式保存且仍合法的设置，或目录里的经验证默认值；提交前展示结果。旧模型的强度、预算不能未经验证直接套到新模型。
- 参数失效、设置 schema 变化或模型退役时阻止提交并提示重选；不能默默降档、忽略设置、删掉非法字段后继续调用。
- Codex adapter 从本轮已校验快照生成 `-m` 和 `model_reasoning_effort` 参数，保持隔离进程、工具禁用与认证方式。其他协议 adapter 生成对应的请求字段。后端不是任意 CLI/JSON 透传代理。

OpenAI 官方说明中，推理强度的支持值与默认值依模型而异，降低强度通常有利于延迟，但不能替代 Ariadne 实测：[推理说明](https://developers.openai.com/api/docs/guides/reasoning)、[Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。这里不新增某一型号的可用性或速度保证，也不把 API 支持等同于本机 Codex adapter 已验收。

## 6. 从切换到执行的不可变边界

1. 用户打开菜单并选择目标组合；保留未发送文字及附件，不发出模型请求。
2. 前端检查当前连接、operation 和参数，展示生效后的选择；如设置无法持久保存，应明确提示，而非声称“已记住”。
3. 发送前重新核对接收方和同意范围。跨 Provider/连接切换时，重新确认会发送给新接收方的**上下文、既有材料摘录与本轮附件**，不只是附件；同一 Provider 换模型/强度也使绑定旧组合的待发送确认失效。重新确认复用现有知情机制，不增加虚假默认勾选。
4. 原子地冻结当前选择 revision、RuntimeSnapshot、用户意图、当前上下文版本和 consent；异步读取来源期间若选择已变，取消本次提交准备并要求重试，不能混合两个组合。
5. 后端从受信目录与连接状态重新验证准确身份、资格、参数及来源完整性，再交给唯一对应 adapter。浏览器自报“已验证”不构成授权。
6. 生成时禁用当前对话的切换入口。其他页面/标签页更改默认值，不能影响已经发出的请求。返回结果按原快照与原会话归属接收，继续检查 generation、来源和 Working/确认版本；不能仅因全局模型标签改变就丢弃合法旧轮结果。
7. 成功结果仍只形成领域允许的 Working/Proposal 或解释；人工保存权限不变。失败保留输入/资料，显式报错；重试创建新执行，改模型重试必须基于新快照与新的同意。

导入 batch 不使用对话覆盖：在用户确认 Start 时捕获当时的应用默认与设置并冻结整批，处理中不换模型、不改变取消剩余队列的语义。后续打开由该导入生成的对话，可以独立调整未来的对话执行。

## 7. 快照、缓存与历史

扩展 RuntimeSnapshot 时至少增加 `snapshot_contract_version`、`connection_id`、`descriptor_revision`、`settings_schema_version`、完整 `effective_settings` 及 `selection_revision`；准确 provider/model/protocol 和现有 adapter/prompt/schema/delivery/credential_ref 字段保留。确切 schema 名称由实施阶段统一确定。

- 所有影响执行的有效参数、协议/adapter/提示版本、模型与连接身份进入运行指纹，并进入导入 operation identity、幂等与执行缓存键。时间戳、纯展示简称和选择 revision 不代表模型语义改变，不用它们代替有效设置指纹。领域资料/上下文指纹仍独立存在。
- 参数变化不能命中旧运行的“已处理”结果；但不删除或自动重生成旧资料。个人理解/职位概况等既有派生缓存可继续作为历史结果展示，保留原模型/设置来源；用户要求用新配置重算时必须生成独立新执行，不能把旧缓存标成新模型结果。
- 原始材料与已确认版本不因切换而改变；历史对话中的来源身份不改写。2026-09-10 按用户要求，回复气泡不再显示模型与强度标签；本轮准确模型与参数仍保存在执行快照中，不改写为当前菜单值。
- v1 快照原样保留，不能给缺失的强度字段补一个“当时使用 medium”的假事实；缺失字段继续视为“未记录”，不再追加到回复气泡中。旧参数固定值可以在文档中说明，但不是逐轮证据。
- v2 执行拒绝丢失参数的旧请求，兼容失败发生在模型调用前，并提示刷新。历史记录读取与旧请求执行兼容是两个问题；须分别迁移前后端 schema、manifest/signature、请求/回执校验和指纹算法。

## 8. 共用组件与六入口接入

一个 `ComposerModelSelector`（建议名称）挂载到现有共用输入框底部，消费目录、scope、operation、busy 和 selection；它不读取完整简历/职位，不自行调用 Provider，也不自行修改全局默认。首次挂载、重绘和跨页恢复必须避免重复按钮/订阅。

覆盖 Candidate 工作区、Candidate 详情、Job 工作区、Job 详情、个人理解、职位概况六个对话入口。Candidate 的逐条待确认回答与所在 conversation 使用同一有效选择；它仍只回答绑定的卡片/问题，不单独决定模型，也不顺带发送主输入框待发附件。

首页选择器与该组件复用同一目录/解析器；前端预检和后端校验使用同版本的公开能力描述，但后端保有执行权威。新增型号通常只需补目录/设置描述、协议适配与验收证据；新增协议必须扩展 transport adapter，不能把它误说成“加一行配置即可”。

| 阶段 | 主要位置 | 完成条件 |

| A. 目录与选择解析 | `src/runtime_binding.py`、`public/runtime-capability-gate.js`、`app.py`、`src/local_connector.py` | 消除分散的 Sol 特判；复用能力 authority，支持统一简称、连接、scope 与参数描述；不提前解禁其他模型 |
| B. 执行设置贯通 | `data/runtime_snapshot_v1.schema.json` 的版本化后继、`src/execution_contract.py`、`public/runtime-capabilities.js`、各域 snapshot/request、Provider adapters | 每轮准确参数可追溯，CLI/API 实际参数与 UI 一致；更改强度进入指纹；旧请求安全拒绝、旧历史仍可读 |
| C. 共用 UI 与偏好迁移 | `public/runtime-selection.js`、`public/codex-connect.js`、共用 composer、六入口与附件 consent | 首页简称、内部模型/强度调节、对话覆盖/默认、忙态、跨页恢复、迁移提示、接收方重新确认一致 |
| D. 新模型逐个接入 | 同一目录、对应 adapter、现有领域回归与真实执行证据 | 图片与完整视觉 PDF、当前 operation、可调参数均有验证；未通过不出现在可执行选项中 |

A–C 是把当前已接入模型变成完整可调体验的依赖顺序；未完成 B，不能把 C 的图标称为“切换已生效”。D 是后续可复用路线，不在本次架构文档阶段接入 Gemini 或其他型号。

必要验收包括：

- 准确模型/连接身份传入正确 adapter；参数不支持、连接撤销、模型退役、伪造资格全部零模型调用；Local 零 Provider 调用，无静默 fallback。
- 调整后只影响下一轮；另一个对话覆盖不变；同一 conversation 多标签 revision 冲突可见；发送准备竞态、in-flight 变更、取消/重试均不改派。
- 模型/强度指纹隔离、跨模型历史真实、旧快照读取、旧执行拒绝、导入整批冻结、个人理解缓存归属正确。
- 六入口同一选择真正在本轮 CLI/API 生效；逐条回答也遵守。切换不丢草稿/附件；未重新同意时不发资料；失败保留输入与来源，确认数据不变。
- 实际浏览器检查首页简化、弹出菜单、中文/英文标签、键盘/焦点、390 px 窄屏与等待状态；执行 `python3 scripts/check_vi.py` 和相关回归，不扩容历史例外。
- 每个准备开放的模型/强度用合成材料做真实参数、延迟和语义验证。分别记录传输准备、进程启动、Provider 等待、校验/持久化耗时，不把推理强度预设成全部延迟原因，不承诺未经测量的加速倍数。

## 10. 权威关系与本阶段边界

本文补充 [Runtime 主契约](ARIADNE_RUNTIME_EXECUTION_CONTRACT.md)的模型选择与设置层；其“不静默 fallback、快照不可变、全操作多模态、来源完整性、领域隔离及 Human Save”继续有效。旧文中“每次读取全局 Current Runtime”细化为“先受全局模式和首页 Provider 约束，再读取当前 scope 的有效选择”；同 Provider 内保留显式对话偏好。

原架构文档阶段未修改运行代码；本次按用户后续“实现这个功能”完成当前两模型的选择/设置链路。没有新增 Provider/型号，不修改用户已选默认和确认资料，不继承开发任务设置，不宣称已完成速度优化。
