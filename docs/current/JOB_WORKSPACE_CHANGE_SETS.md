# 职位工作空间：对话变更集

更新：2026-09-28。本契约取代对话每轮仅能修改一个 `job_edit` 的协议；旧提案及其审核入口保留兼容。

## 问题与决定

旧架构把存储领域的分离变成了用户意图的分离：模型只读投递阶段/结果，不读备注和求职记录；输出只容纳一个字段，正文编辑又依赖本地关键词路由。即使用户完整说明招聘经过并要求同步，系统也只能产生状态提案。

现在同一职位上下文统一读取、提出修改并审核，底层领域仍各自负责数据规则。一次意图可产生多项语义操作，一份提案展示全部修改，一次人工保存原子提交。AI 判断事实应放在哪里、是否重复、需要补充还是更正；代码不再用修改关键词判断意图。

## 职责

| 层 | 责任 |
| --- | --- |
| 上下文编译 | 当前职位/个人资料，加上该职位已保存的阶段、结果、备注、求职记录文字；记录使用本轮引用，不发送数据库 ID。 |
| 模型语义 | 依据用户请求理解同步范围；区分职位要求、用户跟进事件与个人经历，输出一组 `changes`。材料里的指令不构成修改授权。 |
| 能力契约 | `job_intelligence_contract_v1.json` 的 `change_targets` 定义可写目标、长度、枚举及记录引用要求；Python/浏览器校验一致。 |
| 本地提案编译 | `job-workspace-changes.js` 把语义目标绑定到当前快照，生成前后对照和来源关联；存储 ID、日期、修订号由代码生成。 |
| 审核与持久化 | 共用对话审核卡片、`job-followup-storage.js` 统一保存；成功回合与提案同一事务保存，确认决定与实际变更同一事务保存。 |

## 可表达的变更

- `job.title/company/location/summary/requirements`：职位正文；要求以完整逐行文本提出，完全相同的旧要求保留来源，新要求标记为人工确认的编辑，不借用旧条目的来源。
- `application.stage/outcome/note`：投递阶段、明确结束结果、长期备注。结果必须适用于最终“已结束”阶段；无回复不等于拒绝。
- `journal.append/update/remove`：追加经过、更正已有记录、按用户明确要求移除记录。更正/移除必须引用本轮可见记录，不允许模型提供数据库 ID。更正保留日期、反馈类别和图片，移除保留历史与原件。

事件通常写入求职记录，长期摘要写入备注；默认不把同一段文字重复写进两处。只要求结束但没有经过时可以仅改状态；给出了经过并要求同步时应同时提出事件记录。若状态已经结束、经过尚缺，只补事件。现有记录已包含同一事件时避免重复追加；若无法确定要改哪条记录，提出具体澄清。

## 一致性与来源

提案绑定 Job revision、application revision 和该职位全部可见记录集合的指纹，并保存分析/用户消息关联。生成期间跟进记录变化使回合失效；保存时再次在事务内检查职位存在、三类版本和提案原文/已处理决定。拒绝陈旧提案仍然可行；重复确认或拒绝不可重复写入。手工编辑未结束时不接受对话提案。

所有修改一起成功或一起失败，失败保留待审核提案。只改记录不生成 Job/application 的无关修订；改正文才产生新 Job revision。阶段切换引起的旧结束结果清空也必须出现在预览中。原职位版本、记录历史、图片及 Candidate 数据保持其各自身份。

## 读取与权限边界

进入职位对话前的传输说明明确列出跟进数据，Job 对话同意范围使用新指纹。只发送当前职位最新最多 40 条完整记录、合计最多 24,000 字文字；覆盖不全会明确标记，被省略的记录不可被定向修改。图片仅告知数量与未读取状态，不宣称已检查图片内容。已有记录日期和反馈类别保留；用户明确提供的事件日期可写入新记录正文，新条目使用提案创建时的本地日期。

未确认 Working 职位没有此变更权限。普通讨论/假设/否定修改产生空变更集；Job 对话不改 Candidate 或原始文件。公开搜索回合仍由代码禁止全部写提案，新增 changes 数组也在门禁范围内。扩展能力需要同时补齐目标契约、语义上下文、提案编译、审核和事务测试，不能仅放宽提示词或添加可写存储路径。

## 验证

`job_followup_storage_regression.mjs` 使用真实 HTTP/文件事务验证整组失败回滚、重试、重复决定、跨页冲突、独立领域版本与历史；Job runtime/foundation 验证上下文、字段/引用/枚举、完整输出和作用域拒绝。真实 GPT-6-Astra/high 使用合成资料覆盖状态+事件、已结束补事件、修正记录+备注、仅讨论及材料指令隔离、历史对话补漏、已有记录避免重复；不使用真实用户记录。界面通过隔离浏览器回放该真实合成结果，分别验证保存前后、持久化和布局；这与真实模型调用证据分别记录。
