# 持续个人理解 v1：实现与验收

日期：2026-09-09。依据用户授权实施：跨资料理解、可审阅的个人记忆、有界上下文，并评估完整对话入口。本文描述本阶段实现；此前 [架构审计](ARIADNE_PERSONAL_UNDERSTANDING_AUDIT.md) 保留为历史基线。

## 2026-10-14：已保存更正跨入口一致性

六个对话入口复用当前有效的已保存补充，优先整条提供更正及完整关联证据；整组超预算明确失败，不截断已保存上下文。Candidate 精确限定来源和卡片，跨材料依据只读。四后端校验并实际使用 bundle，成功写事务复核最初捕获的来源/记忆版本。撤回、替换或来源失效后，旧助手结论与旧保存原话引用不重新入模；本轮主动新自述仍允许。原件、可见历史、旧版本和人工 Save 保持，用户确认不等于外部事实认证。

本条取代下文历史描述中“更正及必要依据可能被预算节选/遗漏”的当前行为；其他无关材料仍是有界检索。验收同时修复前后端把“缺少已确认依据”误判为自动保存的文案校验。具体证据、失败及发布边界见[理解一致性修复](UNDERSTANDING_CONSISTENCY_20261014.md)。仅本地源码更新，未升级安装或发布。

## 2026-09-20：对话资料卡提案与传输确认记忆

- 「了解我」不再把明确的“新增资料卡 / 修改现有确认资料卡”请求降级为个人记忆或入口说明。模型可以生成独立的 Candidate 卡片提案；新增支持工作、项目、教育和其他资料卡，修改绑定一张当前确认卡及其版本。删除、合并和隐式建卡仍不开放。
- 卡片提案保持非权威。页面显示类型、标题、分类、副标题、时间、摘要、负责内容和事实，用户可修改后确认保存或暂不采纳；模型回复本身不写确认资料。保存追加确认 revision，原版本保留；目标版本变化时拒绝旧提案。
- 每份卡片提案把本轮请求和模型引用的用户原话保存成浏览器本地 Markdown SourceDocument，并保留模型 Runtime、ProcessingRun、Proposal、ReviewDecision 与来源关系。模型只能引用当前或历史中的用户原话和本轮详细 Candidate 证据，不能把助手建议、职位要求或目录索引写成人经历。
- 个人理解与职位概况底部的“资料范围、接收方与可能费用”确认改为按当前浏览器 origin、operation scope、Provider/model、实际参数与披露版本记忆。重进页面、重开浏览器，或切换后回到同一接收方与参数时可自动恢复确认；更换接收方、模型、实际参数或披露版本不会沿用，用户取消勾选会持久撤回该身份的确认。附件仍保留本轮独立确认。

这项更新没有让普通对话静默改写 Candidate，也没有开放 Job 回写、卡片删除或跨用户同步。离线回归覆盖新增、修改、保存前零确认写入、版本追加、原话来源、确认恢复/撤回和模型切换失效；真实模型语义与实际浏览器布局另按当前阶段证据记录。

## 产品结果与入口

### 2026-09-12 完整证据优先

个人理解与 JD 关联分析复用的个人证据选择器，在当前全部语义能放入调用者给定预算时完整提供正文，不再按单条 6,000 bytes 阈值截取。超预算仍保留原有检索、节选及覆盖说明，总请求上限、记忆撤回/来源绑定和人工保存权限不变。两域理解复用分批及模型配置身份函数，缓存身份格式和领域权限不变。架构复核、功能保留表及 Markdown 迁移条件见 [内容架构复核与简化](CONTENT_ARCHITECTURE_SIMPLIFICATION.md)。

### 2026-09-10 连续对话与等待修复

- 普通 DISCUSS 直接编译当前资料、目录、有效记忆和对话，单次模型调用；不再以完成 DISTILL/SYNTHESIZE 为前置条件。「更新理解」仍保留完整分批理解，当前版本/模型配置一致的既有画像可以复用，旧画像不当作最新材料。
- 共用历史编译从最多 4 轮整组装载改为：预算内优先用户原话，最多检查最近 48 个成功/失败的真实用户回合，再分配少量最近助手回复。长助手回复不会阻断更早用户原话；资料版本变化只排除旧助手推断，不清空用户的聊天陈述。对话自述不等于保存或外部验证。超过预算仍会节选/省略，不是无限记忆。
- 被撤回、替换或来源失效的记忆，不通过原始聊天回合重新注入；可见历史保留，Human Save/版本冲突/来源约束不变。当前新陈述仍可显式纠正旧信息。
- 检索对标题命中给予更高排序权重，提供有界资料目录，让模型区分“记录存在但细节未选入”和“没有记录”；这是检索，不冒充语义判断。超过目录/正文预算时不声称掌握全部材料。
- 个人 prompt v5 明确使用对话自述、承认已知角色、不让旧 AI 否认压过用户原话，不编造细节。模型仍只可用当前消息原文生成记忆提案，历史理解不扩展保存权限。
- 合成真实 Codex / gpt-5.6-sol / medium 执行约 23.45 秒，正确承认用户自己发起并独立负责虚构项目，说明尚缺正文，proposals 为空且 persistence=not_written。这不是速度对照实验或固定延迟保证；真正流式传输仍未完成。
- 自动回归覆盖单次直接 DISCUSS、长回复/多轮历史、资料变更、撤回与保存边界；egolite 在实际应用验证编译与合成浏览器内领域执行/回复渲染。真实工作区只做本地只读检查，未向模型发送其正文。证据保留 `.cache/personal-continuity-20260910/`。

## 数据与权限

- 原始 `SourceDocument`、Candidate/Job 确认版本、Working 和历史原地保留。数据库由 15 增量升级到 16；所有既有 opener 使用相同版本和 store 名称，没有删除 store 或重建个人数据。
- 新增六个 store：`personal_memory_revisions`、`personal_memory_proposals`、`personal_memory_decisions`、`personal_understanding_fragments`、`personal_understanding_snapshots`、`personal_conversation_turns`。
- 个人补充分为 FACT、PREFERENCE、GOAL、CORRECTION。模型仅提出 ADD/REPLACE/RETRACT Proposal；必须引用当前用户消息中的原话，关联引用必须来自本轮证据。用户可编辑、保存或暂不采纳。
- Human Save 在同一个[内容库事务](MARKDOWN_CONTENT_STORAGE.md)内（本机原子文件索引／网页端 IndexedDB）检查提案是否已处理、目标记忆版本、关联来源身份/语义/版本，并追加记忆 revision 和 decision。旧版本不覆盖；重复保存、并发覆盖和已变化的来源绑定均被拒绝。文本修正保留既有来源绑定。
- 「不再使用」经用户再次确认后追加 RETRACTED 版本；历史仍可查看，后续当前快照排除。相关来源移除或版本改变时，绑定的补充暂不使用，不能把旧修正套到新资料上。
- 用户确认是用户自述的权威，不等于外部事实核验。偏好和目标不会成为能力证据。个人记忆不是 Candidate 原卡片的静默修改，也不推进 Job 版本。

## 个人理解与上下文

```mermaid
flowchart TD
  A[当前有效个人资料与已保存补充] --> B[按语义指纹分片]
  B --> C[仅理解新增或变化的分片]
  C --> D[复用摘要并重新综合当前资料]
  D --> E[非权威个人理解：关联、依据、未知]
  E --> F[个人对话]
  A --> G[预算内选择相关详细证据]
  G --> F
  G --> J[当前 JD 对话]
  E --> J
  F --> P[待确认的个人补充]
  K[卡片或 JD 用户原话] --> R[用户选择整理并核对发送]
  R --> F
  P --> H[用户明确保存]
  H --> A
```

实现入口：[个人理解领域](../../public/personal-understanding-domain.js)、[记忆事务](../../public/personal-memory-domain.js)、[上下文选择](../../public/personal-context-domain.js)、[共享 Candidate 快照](../../public/job-candidate-context-domain.js)、[Job 编译](../../public/job-conversation-domain.js)、[后端契约](../../src/personal_understanding_runtime.py)。

- 原资料结构化语义完整拆成最多 6,000 UTF-8 bytes 的分片，Unicode 字符不拆断。分片键包含来源身份、语义指纹、片段位置和 prompt 版本。模型必须为每个输入片段返回摘要，不能漏项后声称完整。
- 当前片段摘要全部参加分批综合；跨批沿用的只是本次遍历的部分综合结果。最终理解绑定当前完整快照指纹和 prompt 版本。资料变化或提示版本更新后，旧理解不再用于当前请求；历史仍保留。
- 相同资料重复更新理解为零 Provider 调用。只增加一条短资料时，复用旧分片摘要，理解新片段后重新综合。综合遍历仍随资料数量增长，不声称更新成本恒定。
- 普通讨论总上下文上限 256,000 UTF-8 bytes；详细证据保持既有选择预算。历史最多 500 条用户陈述/200,000 bytes，保留有效原话和回复，超限明确失败；过时助手和已撤回引用按一致性边界排除。分片理解阶段仍为 48,000 bytes。见[连续性与查找](CONVERSATION_CONTINUITY_AND_FIND_20261014.md)。
- JD 的详细个人证据预算 24,000 bytes，历史 200,000 bytes（不静默截断用户要求），变更信息 8,000 bytes；总上下文 256,000 bytes，保留、JD 结构与来源片段边界。完整来源身份/版本 manifest 用于本地与后端观察校验，不作为模型消息全量正文。
- 选择策略是词项相关性、来源多样性与已确认记忆优先的本地检索规则，**不是语义向量检索或 AI 理解**。超长详细条目节选；总数、纳入数、遗漏数、节选数和预算随请求发送。个人页展示最近一轮覆盖和用量。
- 修正记忆与关联材料一起选择。资料达到预算时可能有记忆或材料未入选；模型必须承认覆盖范围，不能声称穷尽所有经历。
- 快照另包含记忆版本标记：即使新增后又停止使用、有效资料集合恢复原状，也不会重新启用保存前的旧聊天或旧理解。标记只用于版本判断，不增加 Provider 正文。
- 有个人记忆后，JD 历史只复用已绑定当前 Candidate 指纹的成功轮次；旧历史保留在界面。涉及旧记忆的变更正文不会通过 delta 回流。停止使用不是物理删除，也不抹除用户主动再次输入的信息。

## 模型与失败行为

复用现有 capability authority 和已验证多模态模型 `deepseek-v4-flash-vision-exp`，未修改用户选择或增加 Provider。新 operation 为 `PERSONAL_UNDERSTANDING_TURN`，分 DISTILL、SYNTHESIZE、DISCUSS 三种阶段；[共享契约](../../data/personal_understanding_contract_v1.json) 与后端签名需一致。

用户勾选当前 Provider/model 的资料传输与费用确认后才能执行；分批处理可能多次调用。Local 可查看和处理已有提案，但不提供伪造模型对话。Model 不可用、传输失败、截断、字段过长、漏摘要、未知引用或提案原话不符时明确失败，无 Local 回退、无确认写入。模型结果先通过结构/引用校验，结构通过仍不等于语义正确。

## 当前限制与后续方向

这完成了「补充 → 审阅保存 → 持久化 → 下轮个人/JD 使用」及「资料变化 → 更新当前理解」的第一版闭环。它让项目能持续积累对用户的可校准理解，仍依赖底层模型，不是替代模型本身。

1. 尚无跨设备账号/同步；浏览器 origin/profile 变化、用户清除网站数据会影响本地记录。未增加备份导出功能。
2. 摘要有损、词项检索可能漏掉语义相关材料，超长材料真实模型与长期多月使用质量尚未验收。不能保证完全理解每份原文或整个人。
3. 新资料的分片摘要可增量复用，但全局综合仍需遍历当前摘要；下一步可在实际规模证据下设计层级摘要和可评估的语义检索。
4. 同名经历不会自动合并，也没有跨来源实体的人工归并界面；矛盾可呈现、可用有来源的修正补充校准，不能自动裁决所有冲突。
5. 资料卡片详情保持当前卡片范围。需要跨材料讨论时进入个人理解；未在卡片旁悄悄扩大全局修改权限。此前审计列出的卡片直接编辑摘要预览问题不属于本阶段改动。
6. 没有新增自动投递、自动简历改写、进度管理平台或通用 Agent 工具执行。完整职业行动/反馈闭环仍需独立定义和验收。
