# 职位投递阶段

更新：2026-09-28。仅记录用户的跟进进度，不修改职位要求、个人资料或模型结论。

## 2026-09-28 整组对话同步（当前行为）

对话现在读取该职位的阶段、结果、备注和求职记录文字，以一组语义变更表达完整请求。用户描述经过并要求同步时，状态与事件一起提案、一起审阅、一起保存；已经结束时可只补缺失经过。正文、备注、结果及记录更正也可在同组处理。模型理解意图和归属，代码校验字段权限、当前版本和事务完整性，不再用本地修改关键词作路由。完整职责、范围、来源与验收见 [职位工作空间变更集](JOB_WORKSPACE_CHANGE_SETS.md)。

以下“仅能修改单一投递状态”的段落是上一版实现记录，由上述契约取代。

## 2026-09-28 对话修改投递状态（上一版）

- 当前已确认职位的 AI 对话会读取这张卡片已保存的投递阶段和结束结果。用户明确要求修改阶段时，模型可以提出 `application_stage` 建议，目标仅限未投递、已投递、推进中、已结束四种有效值；普通分析和项目建议不产生状态修改。
- 建议沿用对话区的修改前/后审核卡片。模型回复和建议保存都不立即改变卡片；用户点击「确认修改」后，才在同一事务写入该职位的 applications 阶段与追加历史，并记录确认决定。「拒绝建议」只记录决定。取消、失败或陈旧建议不覆盖现有状态。
- 阶段提案绑定创建时的职位与 application 修订号。模型生成期间以及用户确认前，若另一页面修改了阶段，当前建议失效。确认时再次检查修订号和已处理决定，阻止重复应用。关闭/重开阶段清空当前结束结果，既有备注、求职记录、旧结果历史和原始职位版本保留；没有因“未通过微信”等描述自动推断简历拒绝或能力不足。
- 职位正文的标题、公司、地点、摘要仍走已有 Job revision 提案；投递阶段在独立 applications 存储中保存，不生成无意义的 Job 正文版本，也不改写 Candidate。投递阶段对话提案只适用于已确认职位卡片；未确认 Working 职位继续使用原有保存流程。
- 合成回归覆盖模型语义输出、非法阶段、事务失败回滚、备注和历史保留、重复决定与跨页冲突；隔离浏览器核对建议展示、进入对话确认、人工保存和详情刷新。浏览器没有调用真实模型，因此不以此证明模型对任意自然语言的理解质量。

## 2026-09-25 快速输入修订（当前行为）

以下取代上一版的手动发生日期输入，其余统一保存、历史与原图保留边界不变。

- 每组只填写内容和图片。新组自动使用创建时的本地日期，旧 `observed_on` 原样保留，已存记录仍按日期与创建时间正序展示。
- 图片区支持拖拽、直接粘贴和点击选择；内容框粘贴图片也进入当前组。纯文字按原有文本框行为粘贴，不主动读取系统剪贴板。三种输入共用既有格式、数量、大小、解码和像素限制；失败保留原输入，追加图片不重建已有原图身份。
- 添加更多以淡入和高度展开出现，删除以淡出和高度收起退出，使用现有 VI motion tokens；开启减少动态效果则跳过动画。其余组 DOM、文字、图片与光标不随增删重建；动作完成后移焦到新内容框或添加更多按钮。
- 图片准备与增删动画期间阻止并发编辑/保存；所有改动仍是草稿，只有底部统一保存才提交，取消恢复已存内容。无 schema/持久化权限扩展。
- 验证：journal/统一存储/详情接线回归及 VI；egolite 验证三种图片入口、正常文字粘贴、图片限制与失败保留、多组隔离、保存/取消、实际动效和减少动态效果。截图接口超时后以原生 WebKit 检查最终字段层级与图片区域；证据在 `.cache/job-journal-input-20260925/`。

## 2026-09-24 统一编辑修订

以下取代本页旧版的独立备注保存、独立追加表单和倒序显示方式；历史实现与验收记录保留。

- 详情默认只读，点击面板「编辑」后才能修改正文、备注和求职记录。共用编辑控制器管理状态，底部只有一组「保存 / 取消」。保存失败保持整份草稿；取消不写入资料。
- 「备注」编辑为一个大文本框（最多 300 字），查看时按非空行复用任职要求的逐行编号样式。没有“可选”或独立保存按钮；已结束职位的结果也随统一保存提交。
- 求职记录编辑时每组提供发生日期、内容（最多 6,000 字）和图片；「添加更多」增加一组，已有记录可编辑或删除。空的新组忽略，已有记录清空后必须补充内容或明确点击删除。移除旧说明和反馈类型下拉，旧反馈类型仍保留并展示。
- 日期从早到晚，同日按创建时间和稳定 ID 排序。图片以缩略图展示，点击在当前页面对话框放大，支持关闭按钮、遮罩及 Escape。每条最多 4 张 PNG/JPEG/WebP，单张 5 MB、合计 12 MB、3,000 万像素；原图保留。
- `job-followup-storage.js` 将旧 applications/journal 库一次性复制到 `job-radar-local-first-v1` 的同名 store，并在同一事务写迁移标记；旧数据库原地保留，不重复导入或复活删除项。schema 19 新增 `applications`、`job_journal_entries`、`job_journal_images`、`job_followup_migrations`，Web Markdown IndexedDB 与本机文件库均适用。
- 统一保存是单个数据库事务：校验当前 Job revision（或演示卡版本）、application revision 和该职位记录集合指纹，再一起提交正文、备注、记录和图片引用。失效或任一步失败整批不生效；不允许其他职位或已删除记录的 ID 被覆写。修改旧记录保留历史和旧图片，删除仅标记不展示；旧文件保留。仅改备注/记录不生成无意义的 Job revision。
- 阶段仍由职位库下拉主动切换。备注/记录不会自行改变阶段、Candidate、个人理解或 AI 上下文，不自动调用模型。
- 验证：`tests/job_followup_storage_regression.mjs` 覆盖真实 HTTP/落盘、旧数据迁移、整批失败/重试、原图保留、跨页冲突、删除后迁移不复活、Job revision 和 Candidate 隔离。128/128 自动回归与 VI 检查通过；egolite 验证独立详情、iframe、1280/390px、保存/取消/删除、图片放大、刷新和失败保留；合成证据见 `.cache/job-unified-edit-20260924/`。旧 `job_application_browser_qa.cjs` 是历史独立保存流程的验收脚本，不适用于本次统一编辑入口。

## 2026-09-24 求职记录

- 详情新增独立的「求职记录」时间线，支持发生日期、用户选择的反馈类型、最多 6,000 字文字及 PNG/JPEG/WebP 图片。反馈包括进展、已读未回、明确拒绝、持续无回复、面试邀请、Offer 和其他；不从无回复推断拒绝或能力不足。文字与图片至少提供一项。
- 每条最多 4 张图，单图 5 MB、合计 12 MB，解码后最多 3,000 万像素。预览、保存前移除、取消及保存失败保留输入；原图不压缩、不替换。保存后按发生日期和记录时间倒序显示，图片可打开查看。阶段和原备注继续独立维护；原备注缩放角已移除。
- `ariadne-job-journal-v1` 注册到现有 Markdown 内容库。`job_journal_entries` 保存 Markdown 正文及原图引用，`job_journal_images` 保存原始 Blob，经现有存储层落盘/浏览器持久化。二者在一个事务追加，只允许 add，重复 ID 拒绝覆盖；图片引用校验职位及条目身份。其他职位的图片不会为当前详情读取；读取列表先取元数据。
- 记录仅为用户自述，不是外部核验结论；本次不调用模型、不自动改变阶段、不注入 AI 对话，不修改 Job/Candidate 的正文、确认版本或来源。旧备注和阶段历史原样保留；没有自动读取邮箱或聊天软件。
- 确认后的个人资料详情隐藏旧的删除/按源移除入口，与确认后的职位详情一致；两类资料继续在资料库的编辑模式下删除卡片，原件与历史保留。历史演示/兼容记录保留现有详情行为。
- 新回归覆盖日期/类型/大小/格式/Markdown 往返和两类删除规则；现有内容库 HTTP/落盘事务、原图、冲突、回滚套件通过。egolite 合成记录验证图文保存、刷新、图片 SHA-256、职位隔离及断网失败保留/重试；截图接口超时后由隔离 Chrome 检查桌面/390px/详情 iframe、重复 ID 拒绝与图片恢复，无页面错误。后续 CDP 缓存干预下出现间歇性脚本缺失，移除测试干预后在独立源快照复验通过；原始失败记录与证据保留 `.cache/job-journal-20260924/`。

## 使用方式

- 职位卡片左上角原「职位描述」标签改为投递状态，点击下拉菜单选择未投递、已投递、推进中、已结束，选择后直接保存，不打开独立页面/进度对话框。旧职位默认未投递，不推断真实投递情况；已有进度不重置。
- 下拉复用首页 `runtime-selector/runtime-menu/runtime-chevron` 动效，保留原卡片标签的圆角形状，不套用首页按钮外形；文字/箭头间距 8 px、内容自适应宽度、整体向左移动 2 px。菜单支持选中勾、方向键/Home/End、Escape/Tab、外侧点击收起及减少动态效果；打开/关闭菜单不写入记录。
- 结束结果及最多 300 字备注只在职位详情的「投递记录」中编辑，浮窗与独立详情页一致。已结束可选结果：简历未通过、面试未通过、已入职、主动放弃、岗位关闭、其他结果。「保存备注」一次保存；取消恢复已存记录，不保存输入。
- 职位库不再设置「关注中／已结束／全部」筛选，全部卡片始终同页显示。未结束职位保持原有相对顺序；选择「已结束」后，该卡片自动移到列表末尾，仍可直接改回其他阶段。
- 已保存原始职位链接的卡片在底部显示「职位链接」及域名/路径，点击在新标签打开原地址；长链接单行省略。没有链接的卡片不显示占位内容，卡片正文仍进入 Ariadne 职位详情。
- 重新开启清除当前结束结果，但保留用户备注及旧阶段历史。卡片正文仍打开原职位详情；状态选择器与正文链接为 DOM 同级元素，视觉位于卡片左上角，避免嵌套交互和误跳转。卡片下方不再显示状态、结果或备注。

## 数据与边界

- `job-application-domain.js` 以稳定的 `job_context_id` 关联记录，经现有内容库保存到 `ariadne-job-applications-v1/applications`（本机文件库或 Web 浏览器库）；旧 IndexedDB 作为迁移备份保留。职位内容更新不会改变跟进记录。
- 当前阶段、结果、备注、修订号和追加历史在同一事务保存；使用期望修订号校验，陈旧页面不能覆盖新记录。状态保存失败恢复原选项并显示原因；备注失败保留输入。其他页面更新时不覆盖正在编辑的备注，可取消重新读取后再保存。
- 同源页面通过 BroadcastChannel/焦点恢复刷新；打开详情时延迟重绘背后的卡片，关闭详情后才更新，保留展开/缩回的源位置。
- 只有用户主动选择状态或点击「保存备注」才写入，不发起模型请求，不把拒绝结果推断为缺少能力。不自动投递，不读取邮箱，不自动判断结果。
- 卡片链接只读取现有 `source_url` 或旧记录的 `imported_from.source_url`，仅接受 HTTP/HTTPS；呈现本身不请求来源站点，也不修改已存职位。
- 刷新保留数据，但不跨浏览器、设备或 origin 同步；浏览器数据被清除仍会丢失。历史目前作为持久化记录保留，没有新增历史浏览页面。
- 卡片的展示顺序不改变「了解职位概况」或其他 AI 对话的上下文范围，也不改变职位记录及投递历史。
