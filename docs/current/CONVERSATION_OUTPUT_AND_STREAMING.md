## 2026-10-14：简历专用交付与参考版式

- 新回复使用 `ariadne-conversation-delivery-v2`，兼容旧 v1 消息与 PDF/DIAGRAM/UNSUPPORTED 数据；四领域、六入口共用原本的一次模型调用，不以本地关键词分类，也不修改模型、强度、工具或保存权限。
- `RESUME` 精确键为 `kind/title/body/nodes/edges/resume`，其中 body 必须为空、nodes/edges 为空，避免与 blocks 形成两份正文。`resume` 精确包含 `template_name/review_notes/layout/blocks`；正文由 blocks 唯一表达。参考名非空时必须对应本轮真实附件，旧标签不能冒充模板访问。
- 支持 A4 单栏、左对齐姓名/章节、章节细线、条目右侧日期/地点、悬挂缩进项目符号和显式换页。layout 限制边距 12–30 mm、正文 9–12 pt、行高 1.15–1.65、姓名 18–28 pt、章节 11–16 pt、章节间距 6–18 pt。最多 160 blocks、2 万 UTF-16 单元、4 页；越界明确失败，不截尾。block 精确包含 `type/text/right/emphasis`，类型为 NAME/CONTACT/SECTION/ENTRY/PARAGRAPH/BULLET/PAGE_BREAK；姓名唯一并在首位，right 只允许 ENTRY，换页不得夹在章节标题与首条之间。
- 模型读取当前参考的全部页面以选择顺序、层级、密度和版式参数。翻译或换版式不能擅自新增栏目、改变目标职位或改写事实。模板例文不充当职业事实；当前更正与材料冲突须解释或提出必要问题。缺少必要身份时不生成占位简历；缺少可省略的年份/日期可留空。尚不支持居中页头、照片、双栏或任意装饰版式的忠实复刻，不宣称像素或字体完全一致。
- `review_notes` 在下载入口旁和聊天中展示，不进入 PDF。简历不打印品牌、仅供参考、草稿、未经核验说明或待补信息。通用 PDF 同样移除导出器强加的品牌/说明，正文原文保留。文件生成仍不确认、修改或保存 Candidate/Job。
- Canvas/JPEG 负责实际中英文字形；只为实际绘制的行附加不可见 Type0/CID + ToUnicode 文字层，保留测得的坐标/字宽、语义绘制顺序以及完整 Unicode grapheme。PDF 可复制、搜索及提取；不等于已完成 PDF/UA、所有 ATS 或跨系统认证。旧 JPEG-only helper 输入仍兼容。文件名只加一次格式扩展名。
- 分页保留章节、短机构/角色条目和首条正文；长条目按行延续。预留有界，连续条目不被合并成不可能同页的大组。现有文件缓存、失效重建、失败重试、迟到丢弃和 Blob 回收边界保留；六页面与懒加载脚本更新缓存版本。

本轮新增 `tests/resume_delivery_regression.py` / `tests/resume_output_regression.mjs`，覆盖前后端形状/几何/私人引用、当前模板可用性、四域不写确认数据、Unicode 文字层、无水印/注记、右对齐与分页。独立 QA 复现并修复长 ENTRY 与短 ENTRY 孤立的两处分页问题，49 个页末边界及极长条目探针通过。20 组相关回归、VI、实际 egolite 下载与桌面/390 px 检查通过；pypdf 与 pdfplumber 对实际两页 PDF 的内容提取一致。

真实合成测试保留当前 GPT-6.1-Sol/high，经现有 App Server 一次调用、完整两页参考 PDF，返回 9 个 RESUME blocks；栏目/分页、当前职责更正与未知信息分离正确，未产生资料/记忆修改。没有重新发送用户职业材料。本机 Skill 9 个受影响文件已备份同步，237 项 hash 全部通过；运行中的旧窗口需退出重开以载入新后端。证据在 `work/resume-audit-20261014/`；整体求职效果、所有语义约束或任意模板质量仍未完成认证，见[审核与用户待选方案](RESUME_AND_CAREER_AUDIT_20261014.md)。

## 2026-09-24 基线：按意图交付文件（简历/PDF限制由上方更新取代）

- 四个领域 Runtime / 六个页面共用 `src/conversation_delivery.py` 与 `public/conversation-output.js`。在原本同一次模型结构化回复中增加可空的 `deliverable`，不增加意图分类调用、不用本地关键词判断用户意图，不修改选定模型、推理强度或工具权限。DISTILL / SYNTHESIZE 不参与交付。
- 普通聊天、解释文件格式、明确只要文字：`null`，只显示文字。要求介绍文件、报告等：`PDF`，由模型写完整文档内容并自动本地排版下载。要求流程图/关系图：`DIAGRAM`，模型给节点和有向边，Canvas 生成真正的图解 PNG，显示预览、可点击放大及下载。
- 照片、插画等创作型图片与其他未实现格式：`UNSUPPORTED`，明确说明能力未接入，不用文字截图或图解冒充。当前未启用 Codex 的 `image_generation`，未接入图片生成服务。
- 交付契约 `ariadne-conversation-delivery-v1`：精确键 `kind/title/body/nodes/edges`；标题至多 100 UTF-16 单元，PDF 正文 20000，图解说明 1200，暂不支持说明 400；图解 1–8 个节点（每个 70）、最多 12 条边（标签 28）。拒绝越界、自环、重复边、外加 URL/路径/脚本字段。内容只作文本/绘图数据，不执行模型代码。
- 先通过原领域动作、身份、版本与来源范围校验，再接受文件；文件契约错误明确失败。前端也校验契约与版本，文件提案随成功助手消息/turn 原子持久化，不进入确认 Candidate/Job。历史记录没有此字段仍正常打开；重开由已保存的提案重新生成 Blob，无需再次调用模型。旧对话不自动补生成文件。
- 各领域的相关历史上下文可带有界文件摘要，明确标记为非确认、可能截断；沿用各域的版本/撤回过滤。不是完整文件记忆或无界上下文，长文件的后半内容可能不在后续请求中。
- 本地生成按目标消息串行处理，避免同时创建多个画布；页面移除/重绘丢弃迟到结果并回收 Blob URL。失败没有下载链接，只显示错误与“重试生成文件”。不自动下载到磁盘，用户点击下载入口决定保存。
- PDF 暂仍采用现有 Canvas/JPEG A4 排版：中文完整、分页，但文字不能选取或搜索，暂无可访问文本层。图解为有界节点连线，不是任意复杂工程图/绘画平台。所有文件保持非确认信息说明，不因下载变成核实事实。

## 2026-09-10 历史：慢回复的已定位原因与当时未完成边界

1. `src/codex_runtime.py` 当前隔离的 `codex exec --json` 路径等待子进程完成，之后解析最终 `agent_message`。前端各领域调用 `response.json()` 等整包。
2. 职位概况在资料或执行配置变化时可能先进行分批 DISTILL / SYNTHESIZE，再 DISCUSS。个人理解已在另一阶段改为当前上下文单次 DISCUSS，不强制先重建画像。
3. `ConversationUI.revealReply` 是拿到完整合规回复后的快速逐字呈现，不是真正流式。本阶段没有把它重新命名为流式，也没有更换模型、推理强度或降低内容校验。

本机 Codex 0.153.4 的 App Server 协议支持 `item/agentMessage/delta` 和结构化 `outputSchema`，但 `app-server` 没有当前 exec 路径使用的 `--ignore-user-config / --ignore-rules` 开关。本次只运行 initialize/config/read，不创建模型线程、不请求模型、不输出凭据：即使关闭现有 feature 列表，配置中仍有两个继承的 MCP server 条目。条目的存在不是工具实际执行的证据，但也不能据此宣称新路径具备现有隔离保证。因此没有将 App Server 替换进生产调用。
