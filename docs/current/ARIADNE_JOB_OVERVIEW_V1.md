# 个人理解与职位概况：独立范围 v1

日期：2026-09-09。依据用户本次要求，把了解个人与了解全部 JD 的对话重心分开。页面布局复用已落地的精简对话样式，本阶段负责领域、上下文、运行与入口接线。

## 2026-09-24：跨职位对话接入当前个人上下文

当前产品契约取代下方 2026-09-09 阶段的“不读取 Candidate”限制。分别建模与分别保存，不代表讨论时隔绝个人与职位。用户在决定选哪个职位之前，就应能结合自己的经历、已保存偏好和多个岗位比较方向。

- `DISTILL / SYNTHESIZE` 仍只发送 Job，形成可复用的职位摘要；`DISCUSS` 使用 `CURRENT_CANDIDATE_AND_JOB_COLLECTION`，复用 `JobCandidateContext.buildSnapshotFromDatabase` 与 `PersonalContext.select/catalog`。不复制档案，不读取其他工作区或 Codex 聊天历史。
- 对话读取当前有效 Candidate、未确认 Working（明确标记）、已保存个人补充及与同一指纹匹配的个人理解。目录和详细证据分别标明覆盖范围；普通对话总个人/职位上下文限 256,000 UTF-8 bytes（分片理解仍限 48,000），个人详细证据最多 24,000 bytes，随 Job 和历史实际占用收缩。原始 PDF/图片不等于每轮全部重发；目录提示不充当未读正文证据。
- 个人资料或职位读取失败直接失败，不以空数组继续调用模型。`AVAILABLE` 与 `NO_ACTIVE_RECORDS` 分开；未入选、节选或原件未附带不能被说成用户从未提供。偏好不是能力证据，缺少证据不是缺少能力。
- 每轮保存 Job 指纹、Candidate aggregate 指纹、prompt 版本和读取覆盖。只有两类指纹及当前 prompt 均相同的旧轮次进入当前上下文；旧轮次保留并标为历史。执行期间任一资料域变化则结果失效。个人更新不污染 Job-only 摘要缓存。派生个人理解始终不是确认事实。
- 结构化引用允许当前详细 Candidate 与 Job 证据，个人来源在回答中显示标题并返回个人资料库；仅在目录里的条目不能支撑详细结论。写入仍仅限概况/分片/本区轮次三个 store，Candidate、Job 和个人补充均无模型确认写权限。
- 传输说明包含个人资料、补充及公开链接。`JOB_OVERVIEW_WITH_PERSONAL_CONTEXT_V2` 与独立 disclosure 版本拒绝沿用旧 Job-only 同意；仍在现有复选框一次确认，不另加弹窗。

### 本轮公开链接读取

[公开网页准备](../../src/public_web_context.py) 在请求、Runtime、传输同意及凭据检查之后，只读取当前 Human 消息中的 HTTP(S) 链接/明确域名（最多两页）。不扫描历史或资料中的链接、不自动跟随页面超链接、不开放 Codex 工具或本机文件权限，不更换模型。每页最多 512 KB、8 秒读取预算、10 KB UTF-8 正文；最多三次重定向，实际连接固定到经核验的公开 IP，每次跳转重新检查地址，禁止登录凭据、非标准端口、本机/私网/链路本地地址及 HTTPS 降级。

网页仅作为未核验外部来源传给同一模型请求；脚本、样式不作为正文。服务器返回来源 URL、最终 URL、时间、hash、节选与状态回执，前端显示可点击来源。只读到静态页面文字，不代表看过图片、整站或登录/脚本内容；`UNREADABLE / LINK_LIMIT` 明确未取得证据，模型应继续利用已保存个人资料，不编造浏览结果。网页不会自动写成个人经历。正文不单独持久化，轮次仅保存来源回执和回答，hash 不等于网页内容已归档。

该路径已在本机 Python Skill 验证；公开 Web/API 尚未部署此次变更。缺少 socket/TLS 能力的运行环境返回未能读取，不声明支持完整网页浏览或搜索。DNS 解析沿用系统 resolver，其等待不受单次 socket 读取超时严格控制。

### 验收依据

离线回归覆盖个人证据与偏好、撤回、版本变化、只读保存、读取失败、空库/局部覆盖、引用、旧同意失效，以及公开 URL 的 SSRF/重定向/内容预算/失败回执。隔离本机 Skill 使用虚构项目与三个 JD 首轮实际调用 `codex / gpt-5.6-sol` 一次：正确使用 12 次访谈、交互原型与远程偏好，区分工程证据缺口，读取 Example Domain 并拒绝把它当作个人项目证据；确认记录与补充逐项未变。浏览器完成桌面、390px、中英传输说明、重开恢复和网络失败草稿恢复。网络阻断的初次测试因 CDP 设置跨工具轮次未保留而额外执行了两轮合成对话，均成功；随后在同一工具轮次设置阻断，得到真实 fetch 失败并恢复草稿。总计三轮真实合成模型调用，无私人材料传输。证据在 `.cache/job-person-20260924/`；不使用私人资料验证模型。

## 2026-09-12 上下文简化更新

普通讨论在全部当前职位语义可放入 18,000 bytes 详细预算且不超过 60 条时，直接执行一次 DISCUSS，保留完整正文而不因单条超过 6,000 bytes 先截取；不再强制先生成概况。若详细证据仍需节选或遗漏，继续沿下文的全量分片/综合路径，避免丢失全部职位概况能力。显式更新和既有缓存继续保留，只有来源与当前模型设置均匹配的概况可入模。

来源、权限、历史和总 context 上限不变。以下关于增量理解的描述仍适用于显式刷新及较大集合；不再是小集合每次对话的必经步骤。完整语义记录不等于每轮发送原始文件；当前内容已接入 [Markdown 内容库](MARKDOWN_CONTENT_STORAGE.md)，由同一文档投影生成本轮 Markdown 上下文；模型与领域权限保持。

## 产品分工

| 入口 | 重点 | 数据及保存权限 |
| --- | --- | --- |
| 个人资料 → 了解我 | 过去项目、经历、职责、决策、成果、协作与做事方式，逐步了解这个人 | 当前有效 Candidate 与个人确认记忆；个人补充仍先审阅、再明确保存 |
| 职位描述 → 了解职位概况 | 汇总添加的全部当前 JD，讨论岗位类型、职责、要求、共性、差异和未知 | 只读当前 Job 集合；只保存派生概况与本区域对话，不读写 Candidate 或个人记忆 |
| 某个 JD 详情 | 结合当前个人资料，讨论自己与这个职位的关系 | 保留既有 Candidate × Job 契约及独立的 Job 修改/人工保存权限 |

个人 prompt 升至 v3，使旧的派生个人理解失效。普通项目回顾不被默认转成求职建议。没有新增通用聊天首页、自动投递或 Provider。

## 当前全部 JD 的精确定义

[Job 概况领域](../../public/job-overview-domain.js) 仅读取 `job_context_revisions`、`context_proposals`、`context_review_decisions`、`source_documents` 四个输入 store。

- 每个 Job 使用最新有效确认 revision；历史版本保留但不重复计算。
- 纳入当前待审阅的 `JOB_CONTEXT` 提案，并标明「未确认草稿」。排除已处理、拒绝、取消、已确认的提案；同一有序来源 bundle 的多次待审尝试只取最新一次。不同来源不会按职位标题自动合并。
- Demo 卡片、旧 SQL/legacy 投影和个人资料不属于该集合。范围与当前 canonical Job 来源对应，不声称扫描任意本地文件或联网检查职位仍在招聘。
- 结论以 JD 标题/公司呈现引用，确认职位可回到详情；未确认草稿链接至 JD 导入工作区。来源引用不能指向不在当前输入范围的职位。

## 增量理解与上下文预算

职位语义去除内部 ID 后，以 UTF-8 预算分片。模型逐片理解新增/变化的 JD，未变化片段复用已有摘要，然后遍历全部当前摘要生成新概况。片段身份绑定 Job 身份、语义和 prompt 版本；不会只按标题复用。

对话采用当前概况、相关详细 JD 和本会话有效历史。整个 context 不超过 256,000 UTF-8 bytes；详细证据不超过 18,000 bytes/60 条，长职位允许明确节选。历史最多 500 条用户陈述/200,000 bytes，保留用户原话及有效助手回复；资料变化仅排除过时结论及被撤回引用，不整体丢弃任务要求。超限明确失败。词项选择只负责检索，不冒充语义理解。见[连续性与查找](CONVERSATION_CONTINUITY_AND_FIND_20261014.md)。

指纹变化后旧概况及旧轮次不再用作当前上下文，但原记录仍保留。模型处理期间若职位变化，本次结果失败，不保存成当前回答。普通讨论不推进任何 Job/Candidate 确认版本。

所有当前 JD 都进入概况综合，不等于每次提问都发送全部原文。摘要有损、详细检索可能漏项；大规模集合的真实语义召回质量尚未充分验收，不保证每轮都完整理解每份原文。具体职位的深入核对仍可进入详情。

## 运行和持久化契约

- [共享清单](../../data/job_overview_contract_v1.json) 与 [Python runtime](../../src/job_overview_runtime.py) 定义独立 `JOB_OVERVIEW_TURN`：DISTILL、SYNTHESIZE、DISCUSS；后端签名先校验再执行。
- 复用已验证的多模态 `deepseek-v4-flash-vision-exp` 能力 authority，不更改用户 Provider/model。运行方式、operation、adapter、prompt、schema、能力和传输确认均须有效。凭据在契约检查后解析，Provider 请求不带本地凭据引用/持久化 ID。
- DISTILL 必须完整覆盖输入引用；综合/对话使用严格只读输出及当前有效引用。缺项、超长、错误类型、未知来源或正文内部引用均失败。Local 零 Provider；Model 失败无 Local 替代、无假回答、无确认写入。
- 数据库 v16 → v17 只添加 `job_overview_fragments`、`job_overview_snapshots`、`job_overview_turns`。所有旧 opener 同步版本；新写入口限定这三个 store，只有执行轮次状态允许更新，摘要/概况追加保留。原文件、Blob、确认版本和个人记忆不覆盖。

## 验证与限制

新增领域与后端回归覆盖两个范围、最新版本、待审/拒绝、增量缓存、无变化零调用、并发失效、长资料预算、引用校验、运行模式和无写入权限。真实验收使用独立 :8021 浏览器 origin 的合成项目/JD，原始私人材料未发送 Provider。

首次真实综合分别触发正文内部引用与 uncertainties 错误类型失败；保留失败记录并加强输出提示，未删弱校验或自动重试。后续真实模型成功保留职位差异、地点冲突、未确认状态及未知。具体回归、浏览器和新位置运行结果见 [项目状态](../../PROJECT_STATUS.md) 本阶段条目；证据保存在忽略目录 `.cache/job-overview-20260909/`。

确认保存只是用户提供材料的确认，不等于招聘方或外部事实核验。职位集合不是整个就业市场样本；本阶段没有实时职位状态查询、跨设备同步、自动 Job 归并或删除功能。模型回答仍可能出现语义或结构错误，失败会明确呈现。
