## 结论

当前结构是**共用代码与领域契约、两种独立运行入口、两份独立资料库**。它仍适合单用户围绕个人资料与职位持续讨论、审阅并保存结果的产品目标。本轮改进主要消除了传输、解析、转图、读取和渲染中的重复工作；没有证据支持此时改造成微服务或引入第二份云端资料事实库。

“共用领域与保存契约”是代码复用关系，不是一个跨端中心服务。契约分别运行于浏览器页面和各自后端；图中的虚线表示复用，实线表示实际调用或存储访问。领域隔离、原始材料完整性、版本冲突和人工保存权限仍由代码约束，模型承担语义理解。

## 两条实际执行路径

**Web：**浏览器加载 Cloudflare Pages 静态页面；模型 POST 经 Pages 的服务绑定转发到 Python Worker，再按 origin、session、Provider 和凭据摘要分配到 Durable Object。通过资格、同意、范围、契约和重复操作检查后，才向相应 API Provider 发送所选材料。普通静态 GET 走 ASSETS，Worker 的普通 GET 不经过 DO，不能把图中的模型请求路径推广到所有请求。来源：[Pages 转发](../../deploy/cloudflare/pages-worker.js)、[Worker](../../deploy/cloudflare/worker.py)、[Web 适配](../../web_app.py)。

Web 的长期资料保存在当前 origin 的 IndexedDB，包括内容、原件和版本。DO 持久保存防重复请求的指纹，不是云端用户资料库；处理请求时服务及 Provider 仍会接触本次已同意发送的材料。“资料本地保存”不代表推理过程从不传输。来源：[浏览器存储](../../public/content-browser-storage.js)、[DO 回执与缓存](../../deploy/cloudflare/worker.py)。

**Skill：**独立 Mac 窗口复用页面，通过回环 HTTP 调用本机 Python。Python 访问本机文件内容库，并通过隔离的 Codex App Server 连接远端模型。模型及强度由实际目录与 Ariadne 能力资格交集决定，独立登录目录不继承本次开发聊天的模型或上下文。浏览器页面通过 `/api/workspace` 操作文件库，不能直接读写磁盘。来源：[产品组合](../../src/product_application.py)、[本机 App Server](../../src/codex_app_server.py)、[模型资格](../../src/codex_models.py)、[文件库](../../src/workspace_storage.py)。

Web 和 Skill 不自动同步资料。换 origin、工作区、电脑或运行产品，不能依靠模型、同名文件或相同账号推断数据已同步。选定本地工作区属于本机资料库选择，不是服务端多账户身份认证。

## 本轮优化落在什么位置

| 层 | 当前职责与变化 | 不应误解为 |
| --- | --- | --- |
| 页面与输入 | 稳定历史节点、页面内草稿、输入更新合并、PDF 导出复用；冲突保留编辑文字 | 跨刷新持久草稿，或浏览器崩溃后的恢复保证 |
| Transport 与会话 | 增量公开输出、请求取消、人工连接续期、原操作绑定和凭据指纹检查 | 自动重试付费推理，或撤销已产生费用 |
| 材料准备 | PDF 元数据预检、整组页数/像素预算、按需完整逐页转图；Skill 使用已保存附件引用 | 截页、降低图片质量、跨请求缓存私人 PDF，或用 OCR 代替视觉输入 |
| 内容库读取 | 共用读取 Promise、按职位查询、按键批读及分块，迁移标记提前判断 | 已建立持久查询索引，或任意规模下恒定时间读取 |
| 内容库写入 | 保留完整读集与 CAS，旧提案同一事务核对版本、生命周期和决定 | 仅凭模型结构输出就自动写入确认资料 |
| 静态发布 | 整个 JS/MJS/CSS 图带内容代号；上一代资源显式保留；HTML/别名重新验证 | 永久兼容所有历史标签页，或已完成正式部署 |
| 质量与交付 | 离线回归、真实浏览器、三种包、真实本地 Workerd/Pyodide、合成性能证据及 CI | 全部模型质量、生产压力或新机器安装已经通过 |

## 客观评价与下一步触发条件

1. **领域边界比文件边界成熟。** Candidate、Job、Proposal 和人工保存权限明确，但 `v1-pages.js` 仍是大闭包。应先抽出可单独验证的页面状态、生命周期和领域适配接口，再分模块；仅拆文件不能证明降低运行负载，也容易破坏跨页草稿与异步请求状态。
2. **内容存储适合当前本机工作区，尚不是通用多用户数据库。** 查询依然扫描 store 并检查 hash，写入保留完整读集与全局锁。只有真实规模下的扫描时间、锁等待、磁盘用量和 p95 成为瓶颈时，才应引入可重建索引或更细锁；索引不能取代原始内容的权威性。
3. **防重复付费优先于透明重试。** DO 分区限制普通并发为 2、持久推理回执为 256；人工续期保持旧操作绑定。暂存结果丢失不自动再次付费生成，属于明确取舍。以后需要更长会话，应设计回执保留与操作身份生命周期，而非简单删除防重记录。
4. **资源预算和取消是有界机制，不是零成本保证。** PDF 输出每 100 ms 检查一次，可短暂超过预算；pdfinfo 仍有约 10 秒超时窗口。取消向上游请求终止，但已经消耗的计算或模型费用无法由客户端保证撤销。
5. **产品价值仍需单独证明。** 局部成本下降不等于模型费用同比下降或职业建议变得更准确。8 个语义情景和回执工具已提供，本轮真实模型评审状态仍是 `NOT_RUN`；真实用户的理解、纠错、保存成功率和任务完成时间尚需验证。

因此，当前合理方向是继续沿同一领域和保存契约演进，以真实工作负载驱动进一步拆分、索引和性能预算。当前不引入微服务、跨端自动同步或未经验证的新 Provider。
